# Cтруктура данных

Структура данных — это способ хранения данных.

Например:

- список (`list`) хранит элементы подряд;
- словарь (`dict`) хранит пары ключ-значение;
- множество (`set`) хранит уникальные элементы;
- стек хранит элементы по принципу последний пришёл — первый ушёл;
- очередь хранит элементы по принципу первый пришёл — первый ушёл.

**Главное правило**

Циклы подряд → складываем

Циклы вложены → умножаем

Например:

```text
n + n + n = 3n → O(n)
n × n = n² → O(n²)
```

### Теперь разберём `O(1)`

```python
x = numbers[0]
```

Неважно, сколько элементов в `numbers`:

```text
10 элементов → 1 операция
1 000 элементов → 1 операция
1 000 000 → 1 операция
```

Поэтому: `O(1)`. Это называется константная сложность.

**Пример**

```text
list → поиск O(n)
set / dict → поиск в среднем O(1)
```

В примере ниже `Time: O(n²)`, `Space: O(1)`

```python
numbers = [1, 2, 3, 4, 5]
for i in numbers:
    for j in numbers:
        ...
```

Используум `set`: 

```python
numbers = [1, 2, 3, 4, 5]
seen = set()
for number in numbers:
    if number in seen:
        return True

    seen.add(number)

return False
```

Здесь:

```python
for → O(n)
number in seen → O(1) в среднем
итого → O(n)
```

Мы получили: `O(n²) → O(n)`

Цена: нам понадобилась дополнительная память для `seen`. То есть:

```text
Было:
Time  → O(n²)
Space → O(1)

Стало:
Time  → O(n)
Space → O(n)
```

Это одна из главных идей алгоритмов:

Иногда мы используем больше памяти, чтобы получить более быстрое выполнение.

### Сложность `O(log n)`

Здесь каждый шаг уменьшает количество элементов примерно в 2 раза.

Есть `1 000 000` отсортированных элементов. Линейный поиск в худшем случае проверит примерно: `1 000 000` элементов. `Binary Search`— примерно сколько делений пополам понадобится, чтобы прийти к одному элементу?

У нас `1 000 000` элементов, и каждый раз мы делим количество пополам:

```text
1 000 000
↓
500 000
↓
250 000
↓
125 000
↓
62 500
↓
31 250
↓
15 625
↓
7 812
↓
3 906
↓
1 953
↓
976
↓
488
↓
244
↓
122
↓
61
↓
30
↓
15
↓
7
↓
3
↓
1
```

Получается примерно 20 шагов. Поэтому: `1 000 000` элементов

```text
O(n) → до ~1 000 000 проверок
O(log n) → ~20 проверок
```

Если у нас `8` элементов и алгоритм каждый раз делит количество элементов пополам: `8 → 4 → 2 → 1`. Сколько шагов примерно потребуется?
Считаем именно переходы:

```text
8 → 4   # 1
4 → 2   # 2
2 → 1   # 3
```

То есть 3 шага. Это и есть: `log₂(8) = 3`. Но важный момент: не надо сейчас заучивать математику логарифмов. Для собеседования на данном этапе достаточно понимать:
`O(log n)` возникает, когда на каждом шаге размер задачи уменьшается в несколько раз, например в `2` раза.


### Сложность `O(n log n)`

`O(n log n)` часто встречается в эффективных алгоритмах сортировки. Упрощённо можно представить:

```text
n элементов
×
log n уровней работы
```

Получаем: `O(n log n)`

Например: `numbers.sort()`. Сортировка имеет сложность порядка: `O(n log n)`

Если после сортировки сделать ещё один проход: 

```python
numbers.sort()
for number in numbers:
    print(number)
```

получаем:
```text
sort() → O(n log n)
for    → O(n)
```
Оставляем наиболее быстро растущую часть: `O(n log n)`. Тоесть: `O(n log n) + O(n) → O(n log n)`. Итого `O(n log n)`

Представь: `n = 16`. Если мы каждый раз делим количество элементов пополам: `16 → 8 → 4 → 2 → 1`. Сколько будет уровней?

Мы считаем переходы до 1:

```text
16 → 8   # 1
 8 → 4   # 2
 4 → 2   # 3
 2 → 1   # 4
```

То есть 4 деления.

Но если считать уровни, включая исходные `16` и конечный `1`:

```text
16   ← уровень 1
 ↓
8    ← уровень 2
 ↓
4    ← уровень 3
 ↓
2    ← уровень 4
 ↓
1    ← уровень 5
```

Поэтому: `4` перехода и `5` уровней

Для `O(n log n)` нам обычно интереснее именно количество уровней деления → log₂(n).

`n log n` → обработали `n` элементов на каждом из `log`-уровней. Например: `n = 16`, `log₂(16) = 4`. `n × log n = 16 × 4 = 64`

### Память Space

Пример, Какой будет `Time: ?` и `Space: ?`:

```python
a = [1, 2, 3, 4]
b = [5, 6, 3, 8]

def find_common(a, b):
    b_set = set(b)   # ← здесь создаём дополнительную структуру

    for x in a:
        if x in b_set:
            return True

    return False
```

Мы создаём: `b_set = set(b)`. Если в `b` находится `m` элементов: `b = [1, 2, 3, ..., m]`, то `b_set = {1, 2, 3, ..., m}`.
Значит дополнительная память: `Space → O(m)`. Сам `a` мы не создаём — он уже был передан функции. Важное правило для `Space`. Когда считаешь память, спрашивай: Что новое создаёт мой алгоритм?

Здесь:

```text
a → уже существует
b → уже существует
b_set  → создаём сами
``
Поэтому:

```text
Создание set → O(m)
Цикл по a → O(n)
Поиск в set → O(1)

Time:
O(m) + O(n × 1)
= O(n + m)

Space:
O(m)
```

### Hash

`dict` и `set` используют хеш-таблицу, благодаря которой поиск обычно занимает `O(1)`.

**Что такое hash?**

```python
users = {
    "Alex": 25,
    "Bob": 30,
    "Eugene": 32,
    "John": 40
}
```

У Python есть функция: `hash("Eugene")`. Она превращает объект в некоторое числовое значение — `хеш`.

Упрощённо:

```text
"Eugene"
    ↓
  hash()
    ↓
  число
    ↓
определённая позиция
```

Поэтому когда мы пишем: `users["Eugene"]`. Python не обязан перебирать все ключи.

### Hash Collison

Что если два разных объекта дадут одно и то же место в таблице?

Например, условно:

```text
"Eugene" → hash → позиция 5
"Alex"   → hash → позиция 5
```

Получается `collision (коллизия)`.

```text
          hash table

позиция 5
   ↓
┌─────────────┐
│ Eugene      │
│ Alex        │
└─────────────┘
```

Python должен каким-то образом разобраться, какой именно ключ мы ищем. Поэтому нельзя говорить: `dict` всегда `O(1)`.

Правильнее: `dict` и `set` имеют `O(1)` в среднем для поиска, вставки и удаления.

## Stack (Стек)

Stack (стек) — это базова структура данных, которая управляет порядком обработки элементов. Работает по принципу: `LIFO — Last In, First Out`. Последний положили → первый достали.

В Python нет отдельного встроенного типа `Stack`. Поэтому стек обычно реализуют через список (`list`). А у списка уже свои методы. `stack = []`

**Основные операции**

| В теории (Stack)    | Python            | Что это значит простыми словами               |
| ------------------- | ----------------- | --------------------------------------------- |
| `push(x)`           | `stack.append(x)` | **Положить элемент наверх стека. Потому что `append()` добавляет элемент в конец списка, а конец списка мы считаем верхушкой стека.**             |
| `pop()`             | `stack.pop()`     | **Убрать и вернуть верхний элемент**          |
| `top()` / `peek()`  | `stack[-1]`       | **Посмотреть верхний элемент, не удаляя его** |
| `isEmpty()`         | `if not stack:`   | **Проверить, пуст ли стек**                   |
| `size()`            | `len(stack)`      | **Сколько элементов сейчас в стеке**          |

## Queue - Очередь

Очередь — структура данных, работающая по принципу: `FIFO — First In, First Out`. Первый вошёл — первый вышел. Как очередь в магазине.

В Python очередь (Queue) реализуется двумя основными способами, но на практике почти всегда используют `collections.deque`. Список `list` использовать не рекомендуется.

```python
from collections import deque
q = deque()
```

| Название операции  | Как называется   | Команда в Python          | Что делает                               |
| ------------------ | ---------------- | ------------------------- | ---------------------------------------- |
| Добавить в очередь | **enqueue**      | `q.append(x)`             | Добавляет элемент **в конец** очереди    |
| Удалить из очереди | **dequeue**      | `q.popleft()`             | Удаляет и возвращает **первый** элемент  |
| Посмотреть первый  | **peek / front** | `q[0]`                    | Показывает первый элемент, **не удаляя** |
| Проверить пустоту  | **isEmpty**      | `len(q) == 0` или `not q` | Возвращает `True`, если очередь пустая   |
| Размер очереди     | **size**         | `len(q)`                  | Количество элементов в очереди           |

Различие между `list` и `deque` в Python

`list` — это динамический массив, удобный для доступа по индексу.

Удаление элемента из начала списка (`pop(0)`) работает за `O(n)`, потому что все элементы сдвигаются.

`list` плохо подходит для реализации очереди с удалением элементов слева.

`deque (collections.deque)` — это двусторонняя очередь.

`deque` поддерживает добавление и удаление элементов с обоих концов за `O(1)`.

Метод `popleft()` в `deque` удаляет первый элемент без сдвига остальных.

`deque` лучше всего подходит для задач типа «скользящее окно» (sliding window).

Для учебных примеров можно использовать `list`, но в production и на собеседовании предпочтительнее `deque`.

```python
from collections import deque

q = deque()

q.append(5)        # enqueue
q.append(10)

first = q[0]       # peek
removed = q.popleft()  # dequeue

empty = not q      # isEmpty
```

```python
from collections import deque

d = deque([1, 2, 3])

d.append(4)       # справа
d.appendleft(0)   # слева

d.pop()           # удалить справа
d.popleft()       # удалить слева

Все эти операции: O(1)
```
